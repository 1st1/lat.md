# Batch 02: Markdown links

All 10 exact historical queries (q011–q020) were run using the frozen current index and local MiniLM. Every result was graded against documentation and independent source/fixture searches. This is agent judgment, not a human benchmark.

Eight default-top-five verdicts are good; two are partial. No query was poor or lacked an indexed core answer.

- Strongest successes: q013 returns arbitrary repository-path acceptance at rank 1 and the exact unsupported-navigation constraint at rank 2; q018 returns the precise ordinary-GitHub-only versus wiki-both-forms spec at rank 1; q020 returns external parser dispatch, grammar and AST fields across all top five.
- q012 is partial: external default extensions rank 3, but local optional `.md` rules rank 6, behind generic/arbitrary repository path validation. Configuration schema is not in top 10. The wrong subtopic also wins semantic rank (repository path acceptance 1 versus local Resolution Rules 15), so this is not demonstrably a lexical-only problem.
- q014 is partial: relative/wiki syntax and validation are useful, but Graph semantics/Edges, which explicitly establishes both forms participate in graph edges, is missing from top 10. Source confirms ordinary Markdown edges are included.
- q016 answers core heading compatibility well but misses the exact section-command compatibility spec from top 10. q019 covers normalization/duplicates; no dedicated indexed Unicode policy was found, so Unicode omission is not scored as a ranking failure.
- q017 finds the fixed packed-definition behavior at rank 2; test assertions confirm two same-line definitions are diagnosed. Treat historical defect wording as context, not evidence of a current bug.

Hypothesis for follow-up: compound intent decomposition or facet coverage may improve q012/q014, but these observations do not establish that changing RRF globally will help. Focused Markdown behavior searches already work well.
